## Общий каталог и матрица доступа

Общий каталог: `/srv/bilet4-team`, владелец и группа: `root:b4team`, режим: `2770` (`rwxrws---`). SGID обеспечивает наследование группы каталога новыми объектами. При `umask 0002` созданный учебный файл `shared.txt` получил права `0664` и группу `b4team`.

| Пользователь | Проход в каталог | Чтение shared.txt | Изменение shared.txt |
| --- | --- | --- | --- |
| `b4alice` | Да | Да | Да |
| `b4bob` | Да | Да | Да |
| `b4guest` | Нет | Нет | Нет |

Запись от `b4bob` завершилась успешно. Попытка чтения от `b4guest` завершилась сообщением `Permission denied` и кодом `1`.

SGID сам по себе не добавляет право записи. `umask` ограничивает права при создании объектов и не изменяет права существующих файлов.

## Ограниченный sudo

В файле `/etc/sudoers.d/bilet4-alice` настроено правило:

```sudoers
b4alice ALL=(root) NOPASSWD: /usr/bin/id ""
```

Разрешён запуск `/usr/bin/id` от root без аргументов и без запроса пароля. Другая команда (`whoami`) при проверке через `sudo -n` отклоняется. Файл правила принадлежит `root:root` и имеет права `0440`.

## Скрипт аудита и сохранённые результаты

Скрипт и логи сохранены внутри виртуальной машины в `/home/federlv/bilet4-reports`. В репозиторий загружен отчёт со скриншотами их создания и проверки.

Основной скрипт — `audit_users.sh`. Он проверяет наличие аргументов и прав root, существование пользователей, выводит их UID и группы, затем проверяет доступ от имени каждого пользователя через `runuser`.

В скрипте используются `$1`, `$#`, `${9:--}`, `"$@"`, `$?`, функции `audit_user` и `access_check`, циклы `for` и условия `if`. Синтаксис проверен командой `bash -n`, получен код `0`.

Пример выполненного запуска в виртуальной машине:

```bash
cd /home/federlv/bilet4-reports
sudo bash ./audit_users.sh b4alice b4bob b4guest > audit.log 2> audit.err
echo $?
```

| Проверка | Фактический код завершения |
| --- | --- |
| Три существующих пользователя | `0` |
| Несуществующий пользователь | `1` |
| Запуск без аргументов | `2` |

При успешном запуске файл `audit.err` пустой. Ошибочные запуски сохранены отдельно в `missing.log`, `missing.err`, `noargs.log` и `noargs.err`.
